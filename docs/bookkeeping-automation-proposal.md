# 記帳代行 自動化・顧客管理 改善提案書

対象:税理士事務所における「資料回収」「納税アナウンス」の通知自動化と、顧客区分(運転免許モデル)による工数配分の最適化

---

## 1. 基本方針:自動化の狙いは「回収」ではなく「回収レス化」

記帳代行の負担の大半は「資料が来ない・揃わない・不備がある」ことへの追いかけ工数です。
ベストプラクティスの優先順位は次の通りです。

1. **そもそも回収しない状態を作る(回収レス化)** — 銀行・カード・POSをAPI連携し、紙で預かる資料自体を減らす
2. **回収を自動で促す(リマインド自動化)** — 人が「催促の連絡」をしない
3. **回収状況を自動で見える化する(ステータス管理)** — 「誰の何が来ていないか」を探さない
4. **人の手は例外(違反・初心者)だけに使う** — 顧客区分で工数を傾斜配分する

---

## 2. 顧客区分:運転免許モデルの設計

ご提案の「一般・優良・違反・初心者」の4区分は、工数配分の考え方として有効です。
重要なのは **区分を感覚ではなく数値で機械的に判定し、免許更新のように定期見直しする** ことです。

### 2.1 判定基準(例)

| 区分 | 判定基準(直近6ヶ月) | 事務所の対応方針 |
|---|---|---|
| 優良(ゴールド) | 資料提出遅延なし/不備率5%未満/クラウド会計連携済み | フルオート。リマインドも最小限。人は原則触らない |
| 一般(ブルー) | 遅延月1回以内/不備率15%未満 | 自動リマインドのみ。例外発生時だけ担当者が介入 |
| 初心者(若葉) | 顧問開始1年未満 or 経理担当が未経験 | オンボーディングプログラム(後述)。最初の3ヶ月は手厚く、以降は一般へ移行 |
| 違反(レッド) | 遅延月2回以上/不備率15%以上/督促3回超 | エスカレーションルール適用。担当者面談→契約・料金の見直し対象 |

**判定に使うKPI(スプレッドシート等で毎月自動集計)**

- 資料提出の遅延日数(締切からの超過日数)
- 資料不備率(差し戻し件数 ÷ 提出件数)
- 督促回数(自動リマインド後に人が連絡した回数)
- 修正仕訳率(顧客起因の手戻り)

### 2.2 運用ルール

- **更新は四半期ごとに自動判定**(免許更新のイメージ)。担当者の主観で昇格・降格させない
- **区分は顧客にも開示する**。「3ヶ月遅延なしでゴールドになると月次報告が早くなります」のように、顧客側のメリットとセットで伝えると行動が変わる
- **レッド区分には出口を用意する**。①遅延時の割増料金(契約書に明記)、②記帳代行から自計化への切替提案、③改善しない場合の契約見直し。レッドを無限にケアし続ける前提にしない
- **若葉は「期間限定」の区分にする**。12ヶ月で必ず一般 or レッドへ移行。初心者ケアが恒久コスト化するのを防ぐ

## 3. 資料回収の自動化ベストプラクティス

### 3.1 回収レス化(最優先)

| 対象 | 手段 |
|---|---|
| 銀行明細 | freee / マネーフォワード クラウドのAPI連携(全顧客で連携を標準化) |
| クレジットカード | 同上(API連携) |
| 請求書・領収書 | STREAMED、invox、freee/MFのファイルボックスへのスマホ撮影アップロード |
| 給与 | クラウド給与(freee人事労務、マネーフォワード給与)から自動仕訳 |

新規顧問契約時に「連携必須」を契約条件に入れるのが最も効きます。既存顧客は区分更新のタイミングで順次移行。

### 3.2 提出ルートの一本化

- 顧客ごとに **提出用URLを1本に固定**する(Dropboxファイルリクエスト、Google Drive共有フォルダ、freee/MFの証憑ボックスのいずれか)
- 「メール添付・LINE写真・紙持参」の混在が不備と探し物の最大原因。**受付窓口を1つに絞る**ことが自動化の前提条件

### 3.3 リマインドの自動化(標準シナリオ)

顧客マスタ(決算月・締切日・区分)から、月次で以下を自動配信します。

| タイミング | 内容 | 配信先 |
|---|---|---|
| 締切7日前 | 今月の必要資料チェックリスト+提出URL | LINE公式アカウント or メール |
| 締切前日 | 未提出の場合のみリマインド | 同上 |
| 締切超過3日 | 督促(自動)+担当者へアラート | 顧客+社内 |
| 締切超過7日 | 担当者から電話(ここで初めて人が動く)。レッド区分は違反カウント+1 | 社内タスク化 |

**実装手段(コスト順)**

1. **Googleスプレッドシート+GAS(無料)**:顧客マスタと提出ステータスを管理し、GASでメール/LINE通知を自動送信。小規模なら十分
2. **LINE公式アカウント+Lステップ等**:顧客の既読率が高く、督促の到達率がメールより圧倒的に良い。中小企業の社長にはLINEが最強
3. **kintone**:顧客管理・回収ステータス・案件管理を統合。事務所規模が10名超なら投資価値あり
4. **freee/MFの未連携・未添付アラート**:会計ソフト側の機能も併用

### 3.4 チェックリストの顧客別自動生成

「毎月同じものを口頭で伝える」のをやめ、顧客マスタから **その顧客に必要な資料リストを自動生成**して通知に埋め込みます(例:現金商売なら現金出納帳、社保加入なら賃金台帳…)。不備の大半は「何を出せばいいか分かっていない」ことが原因で、これは初心者区分に特に効きます。

## 4. 納税アナウンスの自動化

### 4.1 仕組み:年間税務カレンダー × 顧客属性 = 個社別通知

1. **税目マスタ**を作る(全国共通の期限一覧)
2. **顧客属性**(決算月/消費税の課税・免税/納期特例の有無/中間申告の有無/従業員数)を顧客マスタに持たせる
3. 両者を掛け合わせて **個社別の納税カレンダーを自動生成**し、期限の30日前・7日前に自動通知

### 4.2 税目マスタ(主要なもの)

| 税目 | 期限 | 対象判定 |
|---|---|---|
| 源泉所得税(納期特例) | 7/10・1/20 | 納期特例フラグ |
| 源泉所得税(毎月) | 翌月10日 | 特例なしフラグ |
| 住民税特別徴収 | 翌月10日(特例:6/10・12/10) | 従業員あり |
| 法人税・消費税(確定) | 決算月+2ヶ月 | 決算月から算出 |
| 法人税・消費税(中間) | 中間期+2ヶ月 | 前期税額から判定 |
| 所得税確定申告 | 3/15 | 個人顧客 |
| 個人消費税 | 3/31 | 個人・課税事業者 |
| 所得税予定納税 | 7/31・11/30 | 前年税額から判定 |
| 償却資産申告 | 1/31 | 固定資産あり |
| 法定調書・給与支払報告書 | 1/31 | 給与支払あり |
| 労働保険年度更新 | 6/1〜7/10 | 労保加入 |
| 社会保険算定基礎届 | 7/10 | 社保加入 |

### 4.3 実装と根本対策

- **実装**:スプレッドシートの税目マスタ×顧客マスタをGASで突合し、Googleカレンダー登録+LINE/メール自動配信。半日〜1日の構築工数で回る規模です
- **根本対策**:**振替納税・ダイレクト納付(e-Tax/eLTAX)への移行を全顧客に推進**する。納付書の受け渡しや「納付書が届かない」問い合わせ自体が消えるため、アナウンス業務の総量が減ります。優良区分の条件に「ダイレクト納付設定済み」を入れるのも有効です

## 5. 「経理1年生向けの本を配る」のは早いか?

**結論:本の配布“だけ”では解決しません。ただしオンボーディングキットの一部としては安価で有効です。**

- 市販の経理入門書は **読まれない前提**で考えるべきです(読む習慣のある顧客はそもそも初心者区分で手がかからない)。配布単独では行動変容は起きません
- 一方で書籍は1冊1,500円程度で「教育に投資している事務所」という姿勢を示せるため、**若葉区分の標準装備として渡す価値はあります**
- 本より効果が高いのは、**自事務所仕様の薄い資料**です:
  1. **A4で1〜2枚の「資料の出し方マニュアル」**(提出URL・締切・スマホ撮影の手順)
  2. **勘定科目・領収書の早見表1枚**(「これはどの科目?」の問い合わせが激減)
  3. **5分のスマホ撮影動画**(証憑アップロードの実演。一度作れば全顧客に使い回せる)
  4. **初回3ヶ月の月次15分オンライン面談**(若葉区分のみ。ここで型を付けると以降が自動化に乗る)

つまり「本を配るか、仕組みを作るか」の二択ではなく、**仕組み(締切+自動リマインド+提出URL一本化)が主、教材(自作1枚もの+市販書籍)が従**、という組み合わせが最短です。

## 6. 導入ロードマップ

| フェーズ | 期間 | 内容 |
|---|---|---|
| Phase 1 | 〜1ヶ月 | 顧客マスタ整備(区分判定KPI・決算月・納税属性)/提出URL一本化/自作1枚マニュアル作成 |
| Phase 2 | 1〜3ヶ月 | GAS or LINE公式でリマインド・納税アナウンス自動配信を稼働/若葉オンボーディング開始 |
| Phase 3 | 3〜6ヶ月 | 四半期の区分自動更新を開始/レッド区分の料金・契約ルール適用/銀行・カードAPI連携の全顧客展開 |

### 効果測定KPI

- 督促に使った人時(月次)← 最重要。これが減れば成功
- 締切内提出率(区分別)
- 資料不備率
- 若葉→一般への移行率(12ヶ月以内)
- レッド区分の顧客数と粗利(値上げ・契約見直しの判断材料)
