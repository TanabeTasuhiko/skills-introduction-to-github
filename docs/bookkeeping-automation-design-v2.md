# 記帳代行 自動化 詳細設計編(v2)

前回提案書(bookkeeping-automation-proposal.md)へのフィードバックを受けた具体化。

- 教育は書籍配布ではなく **提出フォームの中に埋め込む**(ジャストインタイム教育)
- 運転免許モデルは **契約書・見積システムに組み込み**、納得感のある値上げとNG客の排除に使う
- マイコモンの手入力工程を **スプレッドシート単一マスタ+RPA** で解消する

---

## A. フォーム組込型教育の設計(書籍配布の代替)

### A-1. 考え方:教育は「読む時間」ではなく「提出する瞬間」に行う

参考にされた社労士向け依頼フォームが優れているのは、**教育・条件確認・期待値調整を、顧客が行動する瞬間(フォーム入力中)に済ませている**点です。書籍は「いつか読む」に流れますが、フォームは提出しないと業務が進まないため必ず通過します。

取り入れるべき要素は次の5つです。

| 要素 | 参考フォームでの実装 | 資料回収フォームへの応用 |
|---|---|---|
| ① 利用条件を最初に見せる | 「freee人事労務を利用中」「30名以下」等を冒頭に明示 | 「提出はこのフォームのみ」「締切は毎月◯日」を冒頭に明示。条件を満たさない依頼を入口で弾く |
| ② 見本画像を入力欄の隣に置く | 申告書・納付書の見本サムネイル | 領収書の撮り方見本、通帳コピーの見本を各アップロード欄の隣に配置。「何を出すか」の説明を不要にする |
| ③ 注意事項への同意チェック | 「期限に間に合わない可能性」への事前同意 | 「締切超過時は翌月処理・割増対象」への同意チェック。**割増の根拠がここで作られる** |
| ④ ステップ分割と必須マーク | STEP1〜3、必須バッジ | 基本情報→資料アップロード→確認の3ステップ。迷いをなくす |
| ⑤ 送信後の自動返信 | 受付メールで次の流れを案内 | 受領通知+不足があれば自動で差し戻し理由を返す |

### A-2. フォームに埋め込む教育コンテンツ(経理1年生対策)

書籍の内容のうち実際に必要なのは数ページ分です。それをフォーム内のアコーディオン(折りたたみ)として配置します。

1. **勘定科目・領収書早見表**(「これはどの科目?」を自己解決させる)
2. **よくある不備TOP3と直し方**(差し戻しの主要因を先回りで潰す)
3. **スマホ撮影の5分動画へのリンク**(一度作れば全顧客で使い回し)

→ プロトタイプを `prototype-collection-form.html` として同梱。区分バッジ表示・締切カウントダウン・同意チェック・見本つきチェックリスト・早見表アコーディオンを実装済み。

### A-3. 実装手段の比較

| 手段 | 月額目安 | 向いているケース |
|---|---|---|
| 自作HTML+GAS(送信先をGASのWebアプリに) | 0円 | プロトタイプをほぼそのまま本番化。柔軟性最大 |
| formrun / Tally | 0〜4千円 | ノーコードで早く始めたい。条件分岐・ファイル添付対応 |
| kintoneフォームブリッジ | 1万円〜 | 回収ステータス管理までkintoneで一元化したい場合 |
| freee/MF証憑ボックス+案内ページ | 会計ソフト費用内 | 証憑はソフトに直接、フォームは案内・同意取得に専念 |

推奨:まず**自作HTML(プロトタイプ)+GAS**で1〜2社に試験導入し、型が固まったらフォームサービスに載せ替え。

## B. 契約書・見積システムへの運転免許モデル組込

目的:①データに基づく納得感のある値上げ、②NG客の排除(入口で断る/出口で解約できる)。

### B-1. 名称の使い分け

内部管理では「違反」で構いませんが、**顧客向け表記は「要改善」に言い換えます**。「違反」と通知すると値上げの納得感より反発が先に立つためです。対外表記の例:優良/一般/スタート(初心者)/要改善。

### B-2. 料金体系:基本報酬 × 区分係数

| 区分 | 係数 | 意味づけ(顧客への説明) |
|---|---|---|
| 優良 | 0.95 | 「手間が少ない分お安くしています」— 値下げ原資は要改善区分の割増で賄う |
| 一般 | 1.00 | 標準 |
| スタート | 1.10 | 初年度の教育・伴走コスト。12ヶ月で一般へ移行し自動的に解消 |
| 要改善 | 1.30 | 督促・差し戻し・特急処理の実費。**改善すれば下がることを必ずセットで伝える** |

ポイントは「値上げ」ではなく「区分の結果」として提示することです。判定KPI(遅延日数・不備率・督促回数)を四半期ごとに**区分診断書**として通知し、見積書・請求書に区分名を印字します。数字が根拠になるため、値上げ交渉が「事実の通知」に変わります。

### B-3. 契約条項サンプル

> **第◯条(資料の提出)**
> 1. 甲は、月次の会計資料を毎月◯日(以下「提出期限」)までに、乙の指定する提出フォームにより提出する。
> 2. 提出期限を7日以上超過した場合、当該月の処理は翌月処理となり、乙は当該月の月次報酬に20%の割増報酬を請求できる。
> 3. 資料の不備による差し戻しが同一月に3回以上生じた場合も、前項と同様とする。
>
> **第◯条(顧客区分と報酬の改定)**
> 1. 乙は、資料提出の遅延日数・不備率その他の客観的指標に基づき、甲の顧客区分(優良・一般・スタート・要改善)を四半期ごとに判定し、甲に書面(電磁的方法を含む)で通知する。
> 2. 月次報酬には、直近の判定区分に応じた係数(優良0.95/一般1.00/スタート1.10/要改善1.30)を翌四半期から適用する。
> 3. 要改善区分の判定が2四半期連続した場合、乙は◯ヶ月前の予告をもって本契約を解除できる。

※ 上記は設計用の雛形です。実際の契約書への反映時は文言の最終確認を行ってください。既存顧客への適用は**契約更新時に、区分制度の説明と診断書の提示をセットで**行うのが安全です。

### B-4. 入口スクリーニング(NG客を最初から受けない)

排除コストが最も安いのは入口です。新規問い合わせフォームに次のスコアリングを仕込み、点数で提示料金を自動で変えます。

| 設問 | 配点 |
|---|---|
| クラウド会計を利用中(freee/MF/弥生オンライン) | +2 |
| 社内に経理担当者がいる | +2 |
| 通帳・カードはネット明細を取得できる | +1 |
| 領収書は月ごとに整理されている | +1 |
| 前顧問との解約理由が料金以外 | +1 |
| 過去に無申告・期限後申告がある | −3 |
| 「領収書は袋のまま丸投げしたい」 | −2 |

| 合計点 | 対応 |
|---|---|
| 5点以上 | 標準料金で提示 |
| 2〜4点 | スタート料金(係数1.10)で提示 |
| 1点以下 | 特別料金(係数1.5〜)で提示、または受任しない |

「断る」のではなく「その手間に見合う価格を提示する」形にすると、NG客は価格で自然に離脱し、それでも契約する顧客は採算が合います。

### B-5. 見積システムへの実装

- 見積書テンプレート(スプレッドシート)に「区分」セルを設け、係数を掛けた金額を自動計算
- Misoca・board等の見積ツールを使う場合は、区分別の品目(「月次顧問料(一般)」等)をマスタ登録
- 見積書の備考欄に定型文:「本見積は顧客区分『◯◯』に基づきます。区分は資料提出状況により四半期ごとに見直します」

## C. マイコモンの手入力問題と自動化

### C-1. 現状整理

マイコモン(名南経営)は会計事務所向けグループウェアで、資料回収管理・工数管理・顧問先とのファイル共有などを備えていますが、**公開API・外部システム連携の仕組みは提供されていません**(公式の機能紹介にも連携口の記載なし)。手入力が多いのは製品仕様であり、頑張って使い方を工夫しても解消しない可能性が高いです。

導入がつまずく典型パターンは「顧客マスタや回収状況を、既存の管理表とマイコモンの両方に二重入力している」ことです。APIがなくRPA(Power Automate Desktop等)も採用しない前提では、転記を自動化する手段はありません。したがって方針は一つです:**転記そのものをやめる**。

### C-2. 方針:回収・通知ループをマイコモンの外に出し、月次の入力をゼロにする

- 資料回収と納税アナウンスは **スプレッドシート単一マスタ+GAS+メール/LINE** で完結させる(gas/ の納税通知システムが既にこの構成)
- マイコモンの回収管理・顧問先通知機能は**使わない**と決める。中途半端に併用すると二重入力が復活する
- マイコモンに残すのは、顧客データの月次更新を必要としない機能だけ(工数管理・所内の情報共有・職員研修コンテンツなど)
- どうしてもマイコモン側に顧客情報が必要な機能を残す場合も、入力は**新規契約時の1回だけ**と割り切り、月次の更新はしない

### C-3. 判断フロー

1. マイコモンで**実際に毎週使っている機能**を棚卸しする(契約機能ではなく実利用)
2. 回収管理・顧問先通知が主目的だった → 本書の仕組みに全面移行し、マイコモンは解約または下位プランへの変更でコスト圧縮を検討
3. 工数管理・研修など回収以外の機能を使っている → その機能だけ残し、回収・通知は本書の仕組みへ
4. いずれの場合も、顧客マスタの正本はスプレッドシートに一本化する(フォーム・契約区分・納税カレンダーすべてがこのマスタを参照する)

## 全体像(v2時点)

```
新規問い合わせフォーム(スコアリング) ──→ 受任判定・初期区分・初期料金
        │
        ▼
顧客マスタ(スプレッドシート:単一の真実の源泉)
  ├─ 月次:提出フォーム生成・リマインド配信(GAS+LINE/メール)
  ├─ 月次:提出ステータス自動更新 → 遅延・不備KPIを蓄積
  ├─ 四半期:区分自動判定 → 区分診断書 → 見積・請求へ係数反映
  ├─ 通年:納税カレンダー自動通知
  └─ マイコモンへの転記は行わない(正本はスプレッドシートのみ)
```
